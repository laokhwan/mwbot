# MWIT Robot — Open House Prototype

ต้นแบบเว็บแอปแบบ static สำหรับเปิดบน Google Chrome แบบ Full Screen/Kiosk บนหุ่นยนต์ดินสอ ใช้งานด้วยการแตะและพิมพ์ได้โดยไม่ต้องมี API แบบเสียเงิน ส่วนการพูดและฟังเสียงเป็นความสามารถของเบราว์เซอร์และระบบปฏิบัติการ

> **สำคัญ:** ชื่อสถานที่ เวลา กำหนดการ และคำตอบทั้งหมดในต้นแบบเป็น **placeholder** ต้องให้ผู้รับผิดชอบ MWIT ตรวจสอบและแทนที่ก่อนนำไปใช้จริง

## ไฟล์สำคัญ

- `index.html` — โครงสร้างหน้าจอ
- `styles.css` — สี รูปแบบ Responsive และ animation หุ่นยนต์
- `app.js` — Navigation, TTS, Q&A, Idle reset และ optional Speech-to-Text
- `data.js` — เมนู เนื้อหา และชุดคำถาม-คำตอบที่แก้ไขได้ง่าย
- `audio/` — ไฟล์เสียงภาษาไทยที่สร้างไว้ล่วงหน้า: บทต้อนรับ 1 ไฟล์, เสียงแนะนำเมนู 6 ไฟล์, Q&A ตัวอย่าง 17 ไฟล์ และ fallback 1 ไฟล์
- Q&A แต่ละรายการใน `data.js` มี `id` และ `audio` สำหรับจับคู่คำตอบกับไฟล์ MP3 ส่วน fallback ใช้ `fallbackAudio`
- หน้า Welcome ใช้ 2D puppet ที่วาดด้วย HTML/CSS แยกดวงตาและปาก จึงกะพริบตาและขยับปากขณะพูดได้โดยไม่ต้องโหลดวิดีโอหรือไลบรารีภายนอก

## วิธีเปิดบน Windows / Chrome

### วิธีเร็วที่สุด (ไม่ใช้ไมโครโฟน)

ดับเบิลคลิก `index.html` แล้วเลือกเปิดด้วย Google Chrome การแตะ เมนู การพิมพ์ถาม และ Text-to-Speech ควรทำงานได้ทันที

### วิธีแนะนำ (ใช้ไมโครโฟน)

Chrome อาจไม่อนุญาตไมโครโฟนเมื่อเปิดด้วย `file://` จึงควรเปิดผ่าน local web server:

1. เปิด PowerShell ในโฟลเดอร์นี้
2. ถ้ามี Python ให้รัน `python -m http.server 8080`
3. เปิด Chrome ที่ `http://localhost:8080`
4. เมื่อกดปุ่ม “พูด” ให้เลือก Allow เพื่ออนุญาตไมโครโฟน

ถ้าไม่มี Python สามารถใช้ static web server ภายในเครื่องที่โรงเรียนอนุมัติได้ โดยไม่ต้องแก้โค้ด

## Full Screen และ Kiosk Mode

- Full Screen ชั่วคราว: กด `F11` ใน Chrome (กดอีกครั้งเพื่อออก)
- Kiosk Mode: ปิด Chrome ทุกหน้าต่างก่อน แล้วสร้าง Shortcut โดยใส่ Target เช่น  
  `"C:\Program Files\Google\Chrome\Application\chrome.exe" --kiosk http://localhost:8080`
- หาก Chrome อยู่ตำแหน่งอื่น ให้แก้ path ตามเครื่องจริง
- การออกจาก Kiosk ใช้ `Alt+F4` ผู้ดูแลควรจำกัดการเข้าถึงแป้นพิมพ์ในวันงาน

## การทดสอบลำโพงและไมโครโฟน

1. ตรวจสอบลำโพงใน Windows Settings > System > Sound
2. เปิดเว็บ กด “แตะเพื่อเริ่มต้น” และตรวจว่าได้ยินเสียงภาษาไทย
3. หากเสียงไม่ออก ให้ตรวจ volume, output device และกดเปิดเสียงในหน้าเว็บ
4. ไปเมนู “ถามหุ่นยนต์” ถ้า Chrome รองรับ จะเห็นปุ่ม “พูด”
5. กดปุ่มพูด อนุญาตไมโครโฟน และพูดว่า “ห้องน้ำอยู่ที่ไหน”
6. ระหว่างรับเสียงควรเห็น “กำลังฟัง” จากนั้นเห็นคำถามและได้ยินคำตอบ
7. หากไม่มีปุ่มพูด ให้ใช้การพิมพ์ ซึ่งเป็น fallback หลักและทำงานได้เสมอ

## จุดที่ต้องแก้เป็นข้อมูลจริง

แก้ที่ `data.js` เป็นหลัก:

- `menuItems` — ชื่อเมนูและคำอธิบาย
- `pages.schedule.items` — เวลา กิจกรรม และสถานที่
- `pages.map.locations` — รายชื่อจุดสำคัญ และนำภาพแผนที่จริงมาแทน placeholder
- `pages.about` และ `pages.projects` — ข้อมูลหลักสูตรและโครงงานจริง
- `qa` — คำสำคัญ คำถาม และคำตอบที่ได้รับอนุมัติ
- `fallback` — ข้อความเมื่อระบบไม่เข้าใจ

QR Code ในปัจจุบันเป็นลาย placeholder เท่านั้น ให้สร้าง QR Code จริงเป็นไฟล์ภาพเก็บในโฟลเดอร์เดียวกัน แล้วเปลี่ยนส่วน `.qr-placeholder` ใน `app.js` ให้เป็น `<img>` พร้อมข้อความสำรอง (`alt`) ที่เหมาะสม

## การสร้างเสียง placeholder ผ่าน Google Cloud Shell

หากต้องการสร้างเฉพาะเสียงแนะนำเมนู 6 ไฟล์ ให้ใช้ `tools/generate_menu_audio.py` ผลลัพธ์คือ `mwit-alvis-menu-audio.zip` ซึ่งไม่มีไฟล์ Q&A เดิม จึงไม่เรียก Text-to-Speech ซ้ำโดยไม่จำเป็น

ไฟล์ `tools/generate_placeholder_audio.py` ใช้สร้างเสียงแนะนำเมนู 6 รายการ, Q&A ตัวอย่าง 17 รายการ และ fallback ด้วยโปรไฟล์ `th-TH-Standard-A`, rate `1.08`, pitch `+4` สคริปต์ไม่มี credential และต้องพิมพ์ `YES` ก่อนเรียก Cloud Text-to-Speech ผลลัพธ์จะอยู่ใน `mwit-alvis-placeholder-audio.zip`

ข้อความในสคริปต์เป็น placeholder เช่นเดียวกับ `data.js` เมื่อได้รับข้อมูลจริงต้องแก้ข้อความ ตรวจอนุมัติตาม `CONTENT_GUIDE.md` และสร้างไฟล์เสียงใหม่ก่อนวันงาน

## ข้อจำกัดของระบบเสียงบน Chrome

### speechSynthesis (Text-to-Speech)

- บทต้อนรับ เสียงแนะนำเมนู 6 รายการ Q&A 17 ข้อ และ fallback ใช้ไฟล์ MP3 ที่สร้างไว้ล่วงหน้าเป็นตัวเลือกแรก จึงไม่ขึ้นกับเสียงที่ติดตั้งในเครื่อง
- หากไฟล์เสียงโหลดไม่ได้ ระบบจะใช้ `speechSynthesis` เฉพาะเมื่อพบเสียงภาษาไทยเท่านั้น และจะไม่เลือกเสียงภาษาอื่นมาอ่านภาษาไทย
- เสียงภาษาไทยและคุณภาพเสียงขึ้นกับเสียงที่ติดตั้งใน Windows/Chrome แต่ละเครื่อง
- เครื่องที่ไม่มี voice ภาษาไทยอาจเลือกเสียงสำรองและออกเสียงไม่เป็นธรรมชาติ
- Chrome อาจบล็อกเสียงก่อนผู้ใช้แตะหน้าจอครั้งแรก ต้นแบบจึงเริ่มพูดหลังการกดปุ่ม
- การพูดข้อความยาวอาจหยุดหรือหน่วงบนบางรุ่น ควรใช้คำตอบสั้น
- ปุ่ม “หยุดพูด” หยุดทั้งไฟล์ MP3 และ `speechSynthesis` และอาจมีความหน่วงเล็กน้อยตามอุปกรณ์

### SpeechRecognition (Speech-to-Text)

- เป็น optional enhancement ไม่ใช่แกนหลัก หากไม่รองรับ ปุ่มพูดจะไม่แสดง
- การรองรับขึ้นกับเวอร์ชัน Chrome, ระบบปฏิบัติการ, permission และ policy ของเครื่อง
- ใน Chrome หลายรุ่น การรู้จำเสียงอาจเรียกบริการออนไลน์ของผู้ให้บริการ จึงอาจใช้ไม่ได้เมื่อไม่มีอินเทอร์เน็ต แม้ตัวเว็บทำงานแบบ offline
- ต้องเปิดผ่าน `https://` หรือ `http://localhost` ในหลายกรณี การเปิด `file://` มักใช้ไมโครโฟนไม่ได้
- เสียงรบกวนในงานและไมโครโฟนของหุ่นยนต์มีผลต่อความแม่นยำ จึงต้องคงปุ่มเมนูและช่องพิมพ์ไว้เสมอ
- ผู้ใช้ต้องอนุญาตสิทธิ์ไมโครโฟน และนโยบายองค์กรอาจปิดฟังก์ชันนี้
